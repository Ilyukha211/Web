Тема 3: Ліцензії для створених інформаційних продуктів SYS_INIT_01

Інформаційний продукт — це задокументована інформація, медіа-контент або програмне забезпечення (ПЗ), створене в результаті інтелектуальної діяльності людини, яке має споживчу вартість та призначене для задоволення потреб користувачів у цифровому просторі.

За замовчуванням будь-який вихідний код, цифровий арт чи текст перебуває під повним захистом Авторського права (Copyright). Без явно наданої ліцензії жодна інша особа не має юридичного права копіювати, запускати, модифікувати або розповсюджувати цей продукт (у режимі All Rights Reserved).

Як застосувати ліцензію до свого продукту?

  1. Створити звичайний текстовий файл із назвою LICENSE або LICENSE.txt у кореневому каталозі проекту.
  2. Вставити туди повний офіційний текст обраної ліцензії.
  3. Додати короткий заголовок (SPDX ідентифікатор) на початок кожного файлу з вихідним кодом.

Три стовпи інтелектуальної власності в IT

Правова основа
1. Авторське право (Copyright)

Виникає автоматично з моменту створення твору. Захищає формальне вираження коду від прямого копіювання, але не саму ідею чи алгоритм. Позначається символом ©.

Договірний механізм
2. Програмна Ліцензія

Юридичний договір (контракт) між автором і користувачем. Визначає чіткі дозволи й обмеження щодо використання, модифікації, комерціалізації та розповсюдження.

Свобода коду
3. Концепція Copyleft

Правовий хак (реверсивний механізм): Авторське право використовується для гарантії того, що всі майбутні модифікації продукту залишаться вільними (відкритими) для спільноти.

Архітектура розповсюдження: Open vs Closed CORE_MODULE_02

Фундаментальний поділ усіх програмних продуктів у сучасній IT-індустрії базується на доступності вихідних файлів (Source Code) для перевірки, аудиту та модифікації.

FOSS / Open Source
Відкрите ПЗ (Open Source)

Вихідний код знаходиться у відкритому доступі. Будь-хто може шукати вразливості, виправляти баги та додавати новий функціонал. Захищено відкритими ліцензіями.

  • Приклади: Linux Kernel, Python, Blender, VS Code.
Proprietary / Closed
Закрите ПЗ (Proprietary)

Вихідний код є комерційною таємницею. Користувач купує лише право на запуск скомпільованого бінарного файла. Декомпіляція заборонена EULA.

  • Приклади: Microsoft Windows, macOS, Adobe Photoshop.

Додаткові концепції розповсюдження

SaaS Model
SaaS (Software as a Service)

Хмарна модель (ПЗ як послуга). Користувач не завантажує код, а працює з ним через браузер або API (напр. Google Docs).

Freeware / Shareware
Проміжне ПЗ

Freeware: Безкоштовне для завантаження, але код закритий (Discord, Telegram клієнт). Shareware: Тріальна версія з обмеженням за часом (WinRAR).

Детальний аналіз специфіки

Вірусний ефект
GNU GPLv3 (General Public License)

Якщо ви використовуєте хоча б 1 рядок коду під GPLv3 у своєму проекті й поширюєте цей проект, ви зобов'язані відкрити увесь свій власний код під тією ж ліцензією GPLv3. Це захищає екосистему від корпоративного привласнення.

Corporate Standard
Apache License 2.0

Улюблена ліцензія великих корпорацій (Google, Meta). Дозволяє робити код закритим, але додатково надає "патентну недоторканність" між розробниками та користувачами.

Creative Commons (Медіа та Арт) MEDIA_CORE_04

Не всі інформаційні продукти є програмним кодом. Для цифрового арту, текстів, музики, 3D-моделей та графіки використовується стандартизована родина ліцензій Creative Commons (CC).

CC BY (Attribution)
Із зазначенням авторства

Дозволяє розповсюджувати, редагувати, адаптувати та використовувати твір у комерційних цілях, головна умова — вказати автора першоджерела.

CC BY-SA (ShareAlike)
Поширення на тих самих умовах

Аналог Copyleft для контенту (використовується Вікіпедією). Будь-які похідні або змінені матеріали мають поширюватись під цією ж ліцензією.

CC BY-NC (NonCommercial)
Некомерційне використання

Забороняє використовувати контент для отримання фінансового прибутку. Дозволено лише для особистих, освітніх чи благодійних цілей.

CC BY-ND (NoDerivatives)
Без похідних творів

Дозволяє поширювати твір (навіть комерційно), але суворо забороняє його змінювати, обрізати чи накладати фільтри.

CC0 (Public Domain)
Суспільне надбання

Автор повністю і назавжди відмовляється від усіх авторських прав. Продукт стає надбанням людства. Жодних обмежень.

Кібер-ризики та DevSecOps (Юридичні вразливості) RISK_ANALYTICS_06

Нехтування ліцензійними правилами в комерційній розробці може призвести до багатомільйонних судових позовів (IP Infringement) та примусового закриття проектів.

Критичний ризик
GPL Contamination (Вірусне зараження)

Якщо розробник випадково копіює шматок коду під ліцензією GPLv3 у свій закритий (комерційний) проект, суд може визнати це порушенням і змусити компанію опублікувати весь свій приватний вихідний код у відкритий доступ.

Правовий Хак
Clean Room Design (Чиста кімната)

Метод зворотної розробки, коли одна команда аналізує чужий код і пише специфікацію, а інша команда (яка ніколи не бачила оригінал) пише новий код за цією специфікацією. Унеможливлює звинувачення у крадіжці копірайту.

Зловживання правами
Copyfraud (Копіфрауд) & Patent Trolls

Copyfraud — це висування хибних заяв про наявність авторських прав на матеріали, які вже знаходяться у суспільному надбанні (Public Domain). Патентні тролі — компанії, що скуповують патенти виключно для шантажу та судів з розробниками.

Захист інфраструктури (DevSecOps)

Стандарт Безпеки
Створення SBOM (Software Bill of Materials)
