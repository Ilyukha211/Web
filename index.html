Тема 3: Ліцензії для створених інформаційних продуктів

Інформаційний продукт — це задокументована інформація або програмне забезпечення (ПЗ), створене в результаті інтелектуальної діяльності людини, яке має споживчу вартість та призначене для задоволення потреб користувачів у цифровому просторі.

За замовчуванням будь-який вихідний код перебуває під повним захистом Авторського права (Copyright). Без явно наданої ліцензії жодна інша особа не має юридичного права копіювати, запускати, модифікувати або розповсюджувати цей продукт.

Три стовпи інтелектуальної власності в IT

Правова основа
1. Авторське право (Copyright)

Виникає автоматично з моменту створення образу або тексту програми. Захищає синтаксичну форму вираження коду від прямого копіювання.

Договірний механізм
2. Програмна Ліцензія

Юридичний договір між автором і користувачем. Визначає чіткі умови використання, редагування, комерціалізації та передачі коду.

Свобода коду
3. Концепція Copyleft

Правовий реверсивний механізм: копірайт використовується для того, щоб юридично зафіксувати відкритість усіх майбутніх модифікацій програми.

Інформаційні продукти з вільним і закритим кодом

Фундаментальний поділ усіх програмних продуктів у сучасній IT-індустрії базується на доступності вихідних файлів (Source Code) для перевірки, аудиту та модифікації.

FOSS / Open Source
Відкрите ПЗ (Open Source)

Вихідний код знаходиться у відкритому доступі. Будь-хто може шукати вразливості, виправляти баги та додавати новий функціонал.

  • Приклади: Linux Kernel, Python, PostgreSQL, Blender, VS Code.
Proprietary / Closed
Закрите ПЗ (Proprietary)

Вихідний код є комерційною таємницею компанії-розробника. Користувач купує лише право на запуск скомпільованого бінарного файла (EULA).

  • Приклади: Microsoft Windows, macOS, Adobe Photoshop, MS Office.

Порівняльний детальний аналіз моделей

Критерій оцінки Вільне ПЗ (Open Source) Закрите ПЗ (Proprietary)
Доступ до сирцевого коду 100% відкритий репозиторій (GitHub / GitLab) Прихований, заблокований за стандартами торговельної таємниці
Перевірка безпеки Публічний аудит спільноти (Закон Лінуса) Закритий внутрішній аудит розробника (Security through obscurity)

Глибока розшифровка ключових термінів монетизації та розгортання

SaaS Model
SaaS (Software as a Service)

ПЗ як послуга: Хмарна модель, за якої користувач працює з програмою через веб-браузер або API. Сама програма виконується на серверах розробника, і користувачеві не передається локальний бінарний файл.

Enterprise Tier
Enterprise-збірки

Розширені комерційні версії open-source продуктів, адаптовані під вимоги великого бізнесу: з підтримкою ролей (RBAC), інтеграцією SSO/LDAP, гарантованим SLA та цілодобовою технічною підтримкою (24/7).

EULA Contract
EULA (End User License Agreement)

Ліцензійна угода з кінцевим користувачем: Юридичний договір у закритому ПЗ, що забороняє реверс-інжиніринг, декомпіляцію та передачу програми третім особам.

Dual Licensing
Подвійне ліцензування (Dual-Licensing)

Стратегія, коли розробник видає код під суворою ліцензією (GPL) безкоштовно для FOSS-спільноти, але одночасно продає платну комерційну ліцензію компаніям, які бажають закрити свій код.

Повна матриця та детальний аналіз ліцензій

Відкриті ліцензії поділяються залежно від суворості вимог до збереження відкритості коду у похідних продуктах.

Тип ліцензії Назва ліцензії Закриття похідного коду Патентна гарантія Ключова вимога
Permissive MIT / BSD 3-Clause Дозволено Ні Збереження тексту авторського копірайту
Permissive + Patents Apache 2.0 Дозволено Так Надання патентних прав + фіксація внесених змін
Weak Copyleft GNU LGPLv3 Дозволено (динамічне зв'язування) Так Модифікації самої бібліотеки мають залишатися відкритими
Strong Copyleft GNU GPLv3 Заборонено Так Увесь похідний продукт зобов'язаний поширюватися під GPLv3
Network Copyleft GNU AGPLv3 Заборонено Так Вимагає відкривати код навіть для хмарних сервісів (SaaS)

Детальна розшифровка специфіки ліцензій

Критично важливо!
GNU AGPLv3 (Affero General Public License)

Мережевий Copyleft (SaaS Loophole Fix): У класичному GPLv3 обов'язок відкривати вихідний код виникав лише при розповсюдженні бінарного файла (дистрибуції). Компанії обходили це, запускаючи GPL-код у хмарі як SaaS і не віддаючи код спільноті. AGPLv3 ліквідує цю лазівку: якщо програма виконується на сервері й надає послуги через мережу Internet, розробник зобов'язаний надати повний вихідний код усім мережевим користувачам.

Strong Copyleft
GNU GPLv3 (General Public License)

Забезпечує «вірусний» ефект. Якщо ви використовуєте бодай один модуль під GPLv3 у своєму проекті й поширюєте скомпільований файл, увесь свій проект ви зобов'язані відкрити під ліцензією GPLv3.

Weak Copyleft
GNU LGPLv3 (Lesser GPL)

Створена для системних бібліотек. Дозволяє зв'язувати (link) закриті комерційні програми з LGPL-бібліотекою без обов'язку відкривати вихідний код основної програми.

Corporate Standard
Apache License 2.0

Пермісивна ліцензія, яка явно надає патентні права від розробників до користувачів та захищає від патентних позовів у корпоративному середовищі.

    # Strong copyleft validation rule

        print("[ALERT] Commercial embedding without source disclosure violates GPLv3!")

    return True

Юридичні ризики, DevSecOps та SBOM

Нехтування ліцензійними правилами в комерційній розробці може призвести до багатомільйонних судових позовів та закриття проектів.

Критичний юридичний ризик
GPL Contamination (Вірусне зараження)

Якщо у закритий комерційний проект випадково потрапляє бібліотека під ліцензією GPLv3, за рішенням суду компанія може бути зобов'язана опублікувати весь свій приватний код у відкритий доступ.

Кібербезпека
Supply Chain Attacks (Ланцюги постачання)

Зловмисники купують або зламують популярні open-source пакети (npm, PyPI) і додають туди шкідливий код. Необхідно проводити постійний аудит залежностей.

Сучасний стандарт DevSecOps
SBOM (Software Bill of Materials)

Повний паспорт програмного забезпечення. Включає перелік усіх використаних бібліотек, версій та ліцензій для швидкого реагування на знайдені вразливості (CVE).

Реальні судові прецеденти в IT:

  • Artifex v. Hancom (2017): Суд визнав, що ліцензія GNU GPL є повноцінним юридичним договором. Компанія Hancom була змушена сплатити штраф за використання коду Ghostscript без дотримання умов GPL.
  • Cisco GPL Lawsuit: Позов від Free Software Foundation змусив компанію Cisco відкрити вихідний код прошивок для роутерів Linksys.
